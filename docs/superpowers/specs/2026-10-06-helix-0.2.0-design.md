# Helix 0.2.0 — Fact checking, Interview mode, Audio sources, G1 panels, Omi & Knowledge — Design

**Date:** 2026-10-06 · **Status:** Draft for review · **Builds on:** `2026-10-04-conversate-g1-g2-design.md` (Plans A, B, D shipped on `feature/conversate`; Plan C superseded by §6 here)

## 1. Intent

Make a live conversation on G1 (Android) and G2 (Even Hub "Helix Live") actively useful: catch wrong
facts and contradictions as they are said, check anything on demand, answer questions fast, coach
both sides of an interview, and put the wearer's own world (stocks, news, notes, Omi memories,
knowledge base) one menu away on G1 — with the audio coming from the glasses mic, phone mic or Omi.

**User said:** fact checker that flags wrong facts and contradictions directly and answers questions
promptly; "check that" when unsure (menu item + ring/touchpad shortcut); quick flag then web
verification; interview mode for being interviewed and for interviewing; choose glasses mic or phone
mic (with phone fallback on G1); G1 menu panels for news, stocks, notes, Omi; Omi recent memories,
Omi as cue context, Omi as mic source; knowledge base grounds cues/answers, has a glasses panel, and
receives session notes/fact-checks. Ship as 0.2.0; 0.1.0 continues through Even Hub review unchanged.

**Assumed:** web verification uses OpenAI's Responses API `web_search` tool with the user's key
(OpenAI provider only); US equities + RSS/Finnhub news per the original spec D2; English.

## 2. Scope and plans

| Plan | Contents | Apps |
|---|---|---|
| **E** | Fact checker (quick flag + web verify + contradictions + "Check that"), prompt-answer latency, Interview modes | shared contract, Android G1, G2 Hub |
| **F** | Audio source selector: Phone mic / G1 glasses mic (LC3) / Omi, with fallback | Android G1 (G2 already has Glasses/Phone) |
| **G** | G1 menu panels: Stocks, News, Notes, Omi memories, Knowledge; knowledge + Omi grounding; auto-save to knowledge | Android G1 |

Order: E → G → F (F needs on-glasses LC3 verification and carries the most hardware risk).
G2 in 0.2.0 gets Plan E only (no knowledge base or Omi exists in the Hub app).

## 3. Shared contract changes (`conversate-core/`)

- **Cue types** (priority): `ANSWER 6`, `FACT 5`, `CONFLICT 5`, `CHECK 5`, `FOLLOW_UP 4`, `RED_FLAG 4`,
  `QUOTE 4`, `HEADLINE 3`, `BIO/CONCEPT 2`, `NEXT_Q 2`, `SUGGESTION 1`, `NOTICE 0`. Labels:
  `FACT CHECK`, `CONFLICT`, `CHECK`, `ASK NEXT`, `RED FLAG`, `NEXT Q`.
- **Cue lifecycle:** a cue may be **updated in place** (`id` stable) — used when web verification
  upgrades a quick flag (`FACT?` → `FACT ✗ … (source)`) — or **withdrawn** (removed from queue / screen,
  never shown again). New session API: `onCueUpdate(cue)`, `onCueWithdraw(id)`.
- **Session mode:** `CONVERSATION | INTERVIEWEE | INTERVIEWER`, chosen at start. `menu.json` idle
  `start` opens a mode picker (`Conversation`, `I'm interviewed`, `I'm interviewing`) then the Prep
  Note picker. Live menu gains `check` ("Check that") as the first item and `mode` (read-only label).
- **CHECK intent:** new intent `CHECK`. Mapping: menu item `check`; at **live root with no cue shown
  and none pending**, `SELECT` and `NEXT` become `CHECK` (G1 right tap, R1 tap, G2 click). BACK is
  unchanged (G2 root double-tap = system exit, review rule).
- **Prompts:** `prompts/factcheck.v1.json` (claim extraction + verdicts), `prompts/verify.v1.json`
  (web verification), `prompts/interviewee.v1.json`, `prompts/interviewer.v1.json`.
- **Vectors:** new `vectors/session-factcheck.json`, `session-interview.json`, `factcheck-parse.json`.

## 4. Fact checker (Plan E)

### 4.1 Pipeline
1. **Claim pass** (on each final, shares the cue engine debounce, 1.5 s): one LLM call over the last
   60 s + a **claim ledger** (≤40 short claims from the last 10 min) returns
   `{claims:[{text, speaker?, verdict: wrong|conflict|ok|unsure, confidence 0–1, correction?, conflictsWith?}]}`.
2. **Quick flag:** `wrong` with confidence ≥ 0.75 → `FACT` cue `title "Check: <topic>"`, body
   `"<claim> → likely <correction>"`, marked unverified (`FACT?`). `conflict` ≥ 0.7 → `CONFLICT` cue,
   body `Earlier: "<x>" / Now: "<y>"`. Max 1 fact/conflict cue per 15 s; ANSWER still pre-empts.
3. **Web verify** (FACT only, OpenAI provider only): Responses API with `web_search` tool, ≤8 s
   timeout → `confirmed` updates the cue in place (`FACT ✗`, source domain, detail = short
   explanation + URL); `refuted` withdraws it; timeout/error leaves it as `FACT?`.
4. **Ledger:** every `ok`/`wrong` claim is appended (deduped by normalized text) so later statements
   can be compared; cleared at session end.

### 4.2 "Check that" (on demand)
`CHECK` intent → immediately (ignores the cue gap) runs claim pass on the last 30 s, then web verify on
the top claim; shows a `CHECK` cue: `"Checking…"` → `✓ Correct: …` / `✗ <correction>` /
`? Couldn't verify`. Always shows a result. One check in flight; a second CHECK while running is ignored.

### 4.3 Prompt answering
ANSWER remains top priority and pre-empts any cue. Targets: first answer text on the lens ≤ 3 s after
the question's final segment (measured and logged as `answerLatencyMs`). Android keeps its existing
question pipeline; G2 keeps `AnswerEngine`.

## 5. Interview mode (Plan E)

| | INTERVIEWEE (they interview me) | INTERVIEWER (I interview them) |
|---|---|---|
| Trigger | other speaker's question (G2: `AudioSpeakerRole.Other`; G1: any detected question) | other speaker's answer segment ends (≥ 2 finals after my question) |
| Output | `ANSWER` cue: first-person, speakable, ≤4 sentences, STAR for behavioural, from Prep Note (résumé/JD) | `FOLLOW_UP` (one question to ask), `RED_FLAG` (vague / inconsistent / contradicts Prep Note résumé), `NEXT_Q` (next uncovered question from Prep Note list) |
| Dwell | 12 s, detail paged | default |
| Suppressed | SUGGESTION | ANSWER, SUGGESTION |
| Fact check | on interviewer's claims | on candidate's claims (feeds RED_FLAG) |

Prep Note conventions (plain text): lines starting `Q:` are the interviewer question list; everything
else is context (résumé, JD, notes).

## 6. G1 menu panels (Plan G)

Live and idle menus gain: `Stocks`, `News`, `Notes`, `Omi`, `Knowledge`. Each opens a `Panel` screen
(list of ≤ 20 rows, 4 visible, `>` cursor; SELECT → detail, BACK → menu).

- **Stocks:** watchlist (phone-edited, ≤10 tickers), Finnhub quote (cache 15 s, refresh every 2 s
  while open); row `NVDA 132.40 +1.2%`; detail = day range, volume, last news headline.
- **News:** Finnhub market news (if key) + user RSS feeds; refresh 5 min while open; detail = LLM
  2-sentence summary on select.
- **Notes:** existing notes store + to-dos; SELECT toggles a to-do; "Quick note" item dictates a note
  (spec 2026-10-04 §6.4 flow).
- **Omi:** recent Omi memories (newest 20) from a periodic Omi import (every 15 min while the app is
  running with an Omi key; manual refresh item); detail = memory text.
- **Knowledge:** most-recent and most-relevant (to the current transcript) knowledge items; detail =
  item text.
- Unavailable sources show one line (`Add a Finnhub key in Settings`, `Add your Omi key`), never crash.

## 7. Knowledge & Omi grounding (Plan G)

- **Grounding:** before each cue / answer / fact-check LLM call, `KnowledgeRepository.search(query,
  3)` over the last 2 finals; results (Omi memories included, since import stores them as knowledge)
  are added to the prompt as `Known context:` lines; cues citing one carry `source="knowledge"` and
  show `(from your notes)` in detail.
- **Auto-save:** at session end, save to knowledge: session summary line, each verified FACT/CONFLICT
  (`Fact-check: <claim> → <correction> (source)`), interviewer RED_FLAGs, and Next Steps — via
  `addIfAbsent` with `source = "Helix session <date>"`.

## 8. Audio sources (Plan F)

Setting **Audio source**: `Phone mic` (default) / `G1 glasses mic` / `Omi`.

- **G1 glasses mic:** send `0x0E 0x01` to the **right** lens (per EvenDemoApp) on session start,
  receive `0xF1` frames (`[0xF1, seq, …LC3 payload]`), decode LC3 (16 kHz, 10 ms frames) with
  Google `liblc3` (Apache-2.0) via NDK/JNI, feed PCM into the existing OpenAI realtime transcriber's
  `AudioCapture` seam. `0x0E 0x00` on stop.
- **Fallback:** no `0xF1` frame for 2 s, a lens disconnect, or a decode error rate > 20 % → switch to
  phone mic, show "Using phone mic" on the phone and as a NOTICE cue; retry glasses mic on next start.
- **Interaction with lens clearing:** Conversate clears with `0x18`; verify on hardware whether `0x18`
  stops the glasses mic (probe: start mic → send 0x18 → keep counting 0xF1 frames). If it does,
  Conversate re-sends `0x0E 0x01` after every clear while the glasses-mic source is active.
- **Omi:** uses the existing `OMI` transcript source; the Conversate card shows the source picker and
  Start uses the chosen source.

## 9. Error handling
Web verify unavailable (non-OpenAI provider / no network) → quick flags only, labelled `FACT?`.
Knowledge/Omi failures never block cues. LC3 native library missing on an ABI → glasses-mic option
hidden. All LLM failures follow the existing degraded-badge rule.

## 10. Testing
Shared vectors (session-factcheck, session-interview, factcheck-parse) in JUnit + Vitest; unit tests
for ledger dedupe, cue update/withdraw, CHECK mapping at live root, interview triggers, panel
navigation and paging, knowledge prompt injection, auto-save records, LC3 frame parsing + fallback
timer (fake decoder), mockwebserver for Responses/web_search, Finnhub, Omi. Hardware checklist: G1
glasses mic + 0x18 interaction, latency of answer/fact cues, R1 tap = Check that.

## 11. Decisions needing sign-off
- **E1** Web verification only with OpenAI as provider (others: quick flags only).
- **E2** Tap at live root (nothing shown) = Check that, on all devices.
- **E3** G2 0.2.0 gets fact-check + interview only; panels/knowledge/Omi are G1-only for now.
- **E4** Finnhub key (user-supplied) for stocks/market news, plus RSS.
